# AI Agent 原生架构与用户零心智负担设计准则 (Agent-Native Paradigm & Zero Cognitive Burden)

> **文档定位：** 架构设计决策与范式准则 (Architecture Decision Record)  
> **核心思想：** 彻底告别命令行运维心智负担，确立“自然语言意图驱动、工具退居幕后、Agent 自主闭环”的 Agent 原生标准。

---

## 一、 核心宣言：传统开发工具 vs AI Agent 原生的本质分水岭

在传统的开发者工具体系中，工具通常以命令行（CLI）的形式呈现，要求人类开发者记忆命令名称、理解子命令层级、配置复杂的开关参数（如 `--batch-size`、`--clean-processed`、`--execute`、`--profile`）。

**我们必须明确指出：在 AI 时代，强迫用户在终端中敲长命令、记忆技术参数，本质上是一种将机器复杂度和运维心智负担转嫁给人类的倒退。**

AI Agent 时代的核心价值是 **“自然语言意图驱动” 与 “全自动静默治理”**，而不是让用户退化为命令行操作员。

---

## 二、 为什么强调 CLI 机制是“走弯路”？（反模式剖析）

1. **割裂的交互体验 (Breaking Developer Flow)**：
   * 开发者在使用 Cursor、Claude Code、Codex 或 Antigravity 时，核心工作空间是 **代码编辑器与 AI 聊天窗口**。
   * 当开发者需要沉淀知识或排查会话时，强迫其切换终端、查找路径、输入命令，会彻底切断沉浸式的编程心流。
2. **记忆负担膨胀 (Cognitive Overhead)**：
   * 平台参数、过滤正则、工作区 ID、执行模式（Dry-run vs Execute）……这些属于**底层实现细节**，属于机器该管的事，用户根本不需要也不应该关心。
3. **违背了 Agent 的第一性原理 (Violating Agent-First Principle)**：
   * AI Agent 的本质是**拥有工具调用能力与逻辑推演能力的智能协作者**。
   * 如果工具依然面向人类设计复杂的 CLI，Agent 的自动化潜能就被完全浪费了。

---

## 三、 真正“以用户为中心”的 Agent 原生三层架构模型

底层 Python 脚本和数据驱动应当**彻底退居幕后**，仅作为 AI Agent 的**私有调用工具（Headless Primitives）**，对用户暴露的应当是极致平滑的自然交互：

```
                    ┌─────────────────────────────────────────┐
 【用户交互层】      │  1. 自然语言: "帮我沉淀今天 servers 的经验"     │
 (零心智负担)       │  2. Slash Command: /session-distill     │
                    └────────────────────┬────────────────────┘
                                         │ 意图触发
                                         ▼
                    ┌─────────────────────────────────────────┐
 【AI Agent 编排层】 │  - 自动识别当前工程与技术栈画像          │
 (全自动智能闭环)    │  - 批量提取会话 -> 检索代码证据 -> 审计核验 │
                    │  - 晋升实证规则 -> 静默垃圾回收 (GC)      │
                    └────────────────────┬────────────────────┘
                                         │ 内部私有调用
                                         ▼
 【底层支撑工具库】  │  - shared/ 核心提炼引擎                 │
 (完全退居幕后)      │  - 7 平台适配器 (SQLite/JSONL 驱动)     │
                    │  - session-analyze / dashboard 诊断原语  │
                    └─────────────────────────────────────────┘
```

## 四、 核心场景的无感化交互范例

### 场景 1：一键知识沉淀与代码实证闭环
* **用户行为**：输入 `/session-distill` 或对 AI 说 *“把今天 servers 的改动和决策沉淀进知识库”*。
* **Agent 后台自治**：
  1. 自动定位当前活跃工程目录（如 `E:\project\servers`）；
  2. 自动分批提取未蒸馏会话，生成假设列表；
  3. AI 自主调用 `view_file`、`git diff`、`grep` 搜集当前 HEAD 代码证据；
  4. 自动剔除过时/失实结论，将已验证的 `ANSWERED` 规则写入 `session-knowledge-base.md`；
  5. 自动完成中间解析分片与临时缓存的清理（Garbage Collection）；
* **用户端交付**：
  > “已为您自动完成 3 条历史会话的提炼，核验并通过 1 条业务实证规则（已标准化写入知识库），临时缓存已自动清理。”

### 场景 2：一键状态感知
* **用户行为**：*“查看当前会话蒸馏进度”* 或 *“还有未处理的会话吗”*
* **Agent 后台自治**：
  * 静默调用底层 `dashboard` 统计原语，提取全平台数据并转化为自然语言汇报：
  > “当前 servers 工程所有平台的历史会话均已 100% 完成提炼，待处理积压为 0。”

### 场景 3：静默维护与会话瘦身
* **用户行为**：*“帮我清理一下已处理过的历史会话和空白草稿”*
* **Agent 后台自治**：
  * 自动执行带时间戳快照的 SQLite 安全清理与垃圾回收，并自动重载数据库；
  * 直接向用户反馈结果，无需用户配置任何参数。

### 场景 4：隐式知识消费（智能避坑）
* **用户行为**：在日常编码中提问 *“帮我实现微信支付退款接口”*。
* **Agent 后台自治**：
  * 隐式自动检索并加载知识库中的 `[Refund/ActivationCode]`、`[Payment/Cert]` 等实证规则；
  * 自动产出 100% 规避历史踩坑代码（如自动处理长效公钥轮换保护、退款会员权益联动回收）。
  * 用户**既不需要手动运行查询工具，也不需要翻阅历史文档**，知识自然在编码中生效。

## 五、 Skill 契约与实施规范

为保证跨平台（Cursor、Claude Code、Codex、Antigravity、OpenCode 等）的一致性，各平台的 `SKILL.md` 遵循以下硬性准则：

1. **单一意图入口**：
   * 统一通过 `/session-distill` 提供技能，工作流涵盖“扫描 -> 提取 -> 代码实证 -> 晋升 -> GC”全生命周期。
2. **参数完全自治**：
   * 禁止在文档或交互中要求用户手动输入 `--batch-size`、`--project`、`--profile`；所有参数均由 Agent 从当前运行环境自动感知。
3. **静默垃圾回收 (Silent GC)**：
   * 每次提炼成功后，Agent 必须自动完成中间态数据的清理，不让任何临时文件堆积。

---

## 六、 总结

* **把简单留给人类**：人类只需要专注在业务意图与创造性编码上。
* **把复杂度留给 Agent**：数据扫描、模式识别、代码实证核验与垃圾回收全部由 Agent 原生自治闭环。
* **把底层退回原点**：脚本与工具不再是“前台产品”，而是成为高内聚、纯粹、可靠的 Agent 基础设施。
